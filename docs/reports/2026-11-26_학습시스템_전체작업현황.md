- 기준일: 2026-11-26
- 저장소: [g9inlife-blip/study_daily_han](https://github.com/g9inlife-blip/study_daily_han)
- 기준 브랜치: `main`
- 목적: 개인 학습용 문제은행 및 학습·시험 시스템 개발

## 1. 프로젝트 기본 방향

- 기존 `매일공부` 기능을 유지하면서 시험 대비 기능을 별도로 확장한다.
- 문제 데이터는 XML로 저장하고, 향후 데이터베이스로 전환할 수 있도록 필드를 구조화한다.
- 문제 기본 필드: 과목, 학교급(중학교/고등학교), 학년, 범위(목차 기준), 생성 난이도, 통계 난이도, 문제, 정답, 해설, 심화해설, 풀이 인원, 정답 인원.
- 실제 풀이 통계가 없는 문항은 `difficulty2="미산정"`, `attemptCount="0"`, `correctCount="0"`으로 시작한다.
- 해설과 심화해설은 정답 근거뿐 아니라 오답 선택지가 틀린 이유까지 설명하는 방향으로 작성한다.
- 기존 앱의 일일 학습 데이터, 로더, `data/days/`, `manifest.json`, 원본 문제은행은 승인 없이 변경하지 않는다.
- 시험 회차 구성은 원본 문항 XML을 복제·수정하기보다 문항 ID를 참조하는 방식으로 관리한다.

## 2. 중학교 2학년 국어 2학기 기말 범위

교과서: 미래엔 중학교 국어 2-2 (민병곤 외)

| 쪽수 | 단원/학습 내용 |
|---|---|
| 70~87 | 복합양식으로 소통하기 — 글과 자료 평가하며 읽기 |
| 88~119 | 복합양식으로 소통하기 — 복합양식 자료를 활용하여 글 쓰기 |
| 166~187 | 읽고 분석하고 — 점검하고 조정하며 읽기 |
| 188~199 | 읽고 분석하고 — 현실을 재현하는 매체 자료 |

- 120~165쪽은 이번 시험 범위에서 제외.
- 교과서 목차 및 범위 확인 과정에서 일부 범위가 비어 있어 A/B로 표시했던 부분은 목차 기준으로 정리해 관리한다.

위 결과는 수행한 항목별 검사 결과이며, 전체 XML 스키마를 완전 검증했다는 의미는 아니다. 기존 문제는 학습 대상에서 제외하지 않고 유지한다.

## 5. FINAL 예상 기말고사

파일:

- 문항 문제은행: `drafts/question-bank/final/KOR2S2_FINAL_questions.xml`
- 시험 구성: `drafts/question-bank/final/KOR2S2_FINAL_exam.xml`

구성:

- 선택형 23문항, 서답형 3문항, 총 26문항
- 공통 자료 4세트
  - 자료의 신뢰성과 적절성 평가
  - 복합양식 자료를 활용한 글쓰기
  - 점검·조정하며 읽기
  - 현실을 재현하는 매체 자료
- 단원별 설계:
  - 글과 자료 평가하며 읽기: 선택형 6
  - 복합양식 자료 활용 글쓰기: 선택형 6 + 서답형 1
  - 점검·조정하며 읽기: 선택형 5 + 서답형 1
  - 현실을 재현하는 매체 자료: 선택형 6 + 서답형 1
- 선택형은 5지 선다이며 정답·해설·선택지별 오답 심화 설명 포함.
- 서답형은 모범 답안, 부분점수 기준, 심화해설 포함.
- 기존 150문항과 발문 완전 동일 0건.
- 시험 구성의 미존재 문항 참조 0건.
- 기본 태그 짝 검사 통과. 전체 XML 스키마 검증 완료로 간주하지 않는다.

문항별 실제 배점은 2025 원본 시험지의 시각적 배치와 합계 대조가 끝나기 전까지 미확정이다. 현재 웹 응시 화면에서는 균등 배분을 이용해 임시 100점 환산한다.

## 6. 웹 앱 반영 현황

현재 `index.html`에는 다음 기능이 반영되어 있다.

### 과목 탭

- 시험 과목 탭: 국어, 영어, 과학, 역사, 수학
- 국어만 활성화.
- 영어·과학·역사·수학은 비활성 상태이며, 해당 과목의 실제 문제은행과 시험 기능은 아직 준비되지 않았다.

### FINAL 응시

- FINAL 시험 구성 XML과 문제은행 XML을 비동기 로드.
- 시험 구성의 section 순서대로 공통 자료와 문항 렌더링.
- 선택형 자동 채점 및 정답·해설·심화해설 표시.
- 서답형 답안 입력, 모범 답안 및 채점 기준 열람, 0~4점 자기 채점.
- 답안/서답형 점수 누락 시 제출을 막는 입력 검증.
- FINAL 응시 결과를 별도 로컬 저장 키 `study_daily_han_final_exam_results_v1`에 저장.
- FINAL 문항별 응시·정답 통계를 현재 브라우저의 기록에서 집계.
- 문항별 응시 10회 미만은 통계 난이도 미산정. 10회 이상이면 정답률 기준으로 난이도 표시:
  - 40% 이하: 상
  - 40% 초과~70%: 중
  - 70% 초과: 하
- 기존 매일공부 저장 키와 분리되어 있으며, 현재는 서버 동기화나 기기간 기록 공유가 없다.

## 7. 출제 회차 시스템 설계

향후 1~4차 학습 회차는 다음 규칙으로 구현한다.

1. 1차는 전체 시험 범위에서 통합적으로 문항을 편성한다. 단원별로 완전히 분리된 시험을 만들지 않는다.
2. 2차는 1차에서 틀린 문항과 신규 문항을 조합한다.
3. 3차는 2차에서 틀린 문항과 신규 문항을 조합한다.
4. 4차는 3차에서 틀린 문항과 신규 문항을 조합한다.
5. 2~4차의 오답 재출제는 바로 직전 차수의 오답만 기준으로 한다. 이전 차수에서 틀렸더라도 직전 차수에서 맞힌 문항은 자동 재출제하지 않는다.
6. 신규 문항은 미출제 문항, 예비 문항 또는 별도 보충 XML 문항으로 목표 문항 수를 채운다.
7. FINAL은 1~4차 오답 복습이 아니라 독립적인 예상 기말고사로 유지한다.

## 8. 아직 남은 작업

- 1~4차 오답 재출제 + 신규 문항 자동 편성 및 응시 흐름 구현.
- 회차별 응시 이력 및 문항별 통계를 FINAL과 분리하여 저장.
- 신규 보충문항이 필요할 경우 별도 XML로 추가하고 기존 원본 문제은행은 보존.
- 2025 기출 원본 화면과 배점/총점 대조 후 FINAL 배점 확정.
- 실제 브라우저에서 시험 시작, 답안 입력, 제출, 채점, 기록 저장·재로드까지 E2E 테스트.
- 기기간 동기화 및 DB 연동은 추후 단계.

## 9. 작업 시 유의사항

- GitHub 저장소 `g9inlife-blip/study_daily_han` 중심으로 작업한다.
- 브랜치를 새로 만들지 않고 `main`에 직접 반영한다.
- 기존 매일공부 기능과 원본 문제은행을 보호한다.

- 수행하지 않은 테스트나 검증을 완료했다고 보고하지 않는다.
