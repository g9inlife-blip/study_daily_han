- 저장소: `g9inlife-blip/study_daily_han`

- 상태: 설계 초안
- 원칙: 기존 daily 학습 앱, `data/days/`, `manifest.json`, 기존 생성·로딩 로직은 변경하지 않는다.

## 1. 사용자 결정사항

- 단원별 난이도 비율은 조정하지 않는다. 전체 문항을 학습 대상으로 유지한다.
- 3단원 기초문항 추가 보강은 현재 진행하지 않는다.
- 단원별 30문항은 단원 학습용 원본 문제 풀로 보존한다.
- 실제 시험은 전체 시험범위에서 문항을 조합해 출제한다.
- 1차는 전체 범위 통합 출제, 2차는 오답 문항과 신규 문항을 혼합한다.
- FINAL 전용 문항을 별도 제작하고 FINAL 회차에서만 사용한다.
- FINAL은 한 가지 출제자 스타일로 통일한다.
- 2025 기출은 문항을 복사하는 용도가 아니다. 문항 수, 배점, 문항 유형, 발문·보기 구성, 자료 제시 방식 등 출제 형식을 분석해 2026 시험범위에 맞는 새로운 문항을 만든다.
- 2025 기출의 실제 시험범위가 2026 범위와 다를 수 있으므로, 교과서의 2026 시험범위가 내용 출제의 기준이다.

## 3. 회차별 출제 정책

### 1차 — 전체 범위 통합 시험

- 4개 단원에서 모두 문항을 가져온다.
- 한 단원의 30문항을 순서대로 내는 방식은 금지한다.
- 시험지 한 세트 안에서 단원·개념·문항 유형이 섞이도록 구성한다.
- 단원별 출제 수는 시험범위의 분량과 개념 중요도를 고려해 설정한다. 단순히 4등분하지 않는다.
- 동일 세트 안에서 같은 개념을 지나치게 반복하지 않는다.
- 원본 문항 ID를 유지해 정오답 이력을 연결한다.
- 회차별 시험지에는 출제 순서만 별도로 기록한다.

### 2차 — 오답 복습 + 신규 문항

- 1차에서 틀린 문항을 우선 출제한다.
- 오답 문항 수가 목표 문항 수보다 적으면 미출제 문항 또는 예비 풀의 신규 문항으로 채운다.
- 이미 맞힌 문항은 오답 복습 목적의 반복 출제 대상에서 제외한다. 단, 전체 범위 확인을 위한 신규 변형 문항은 가능하다.
- 오답 문항과 신규 문항이 한쪽에 치우치지 않도록 세트 내 비율을 관리한다.
- 재출제 문항은 원본 ID를 유지한다. 신규 변형 문항은 새로운 ID를 부여한다.
- 2차 결과도 누적해 이후 복습 회차에서 오답 상태를 갱신한다.

### FINAL — 전용 최종 모의고사

- FINAL 전용 XML 문제 풀을 별도로 만든다.
- FINAL 전용 문항은 1차·2차·일반 복습에서 출제하지 않는다.
- FINAL은 한 가지 출제자 스타일로 일관되게 구성한다.
- 2025 기출의 문항 수, 총점, 문항별 배점, 객관식·주관식 등 유형 분포, 지문 길이, 자료 배치, 발문 어투, 선택지 구성, 서술형 요구 수준을 분석한다.
- 기출의 소재·정답·문장을 그대로 가져오지 않는다. 2026년 시험범위의 교과 개념과 학습 목표를 사용해 유사한 형식과 사고 과정을 요구하는 새 문항을 만든다.
- 기출의 범위와 2026 범위가 다르면 2026 범위 밖 내용은 FINAL 출제 내용으로 사용하지 않는다.
- FINAL 문항은 교과서 범위 근거, 정답 유일성, 배점에 맞는 답안 분량 및 채점 기준을 개별 검수한다.

## 4. XML 데이터 구조 제안

### 4.1 원본 문항과 회차 구성을 분리

원본 문항 XML은 문제 내용과 학습 메타데이터를 보유한다. 회차 XML은 원본 문항을 어떤 순서로 출제할지만 보유한다.

권장 디렉터리:

```
drafts/question-bank/
├── rebuild/                 # 기존 단원별 원본 풀(보존)
├── final/                   # FINAL 전용 문항 풀
└── sessions/
    └── KOR2S2/
        ├── round1.xml       # 전체 범위 통합 1차
        ├── round2.xml       # 오답 + 신규 2차
        └── final.xml        # FINAL 전용 시험지 구성
```

위 경로는 제안이며, 기존 앱의 데이터 경로와 연결하지 않는다.

### 4.2 회차 XML 예시

```xml
<?xml version="1.0" encoding="utf-8"?>
<examSession schemaVersion="1.0"
             sessionId="KOR2S2-2026-ROUND1"
             subject="국어"
             schoolLevel="중학교"
             grade="2"
             semester="2"
             round="1"
             examScope="70-119;166-199">
  <selectionPolicy>
    <sourcePool>unit1,unit2,unit3,unit4</sourcePool>
    <includeAllUnits>true</includeAllUnits>
    <shuffleQuestions>true</shuffleQuestions>
  </selectionPolicy>
  <items>
    <item order="1" questionRef="KOR2S2-V2-1-004" sourceUnit="1"/>
    <item order="2" questionRef="KOR2S2-V2-3-012" sourceUnit="3"/>
    <item order="3" questionRef="KOR2S2-V2-2-021" sourceUnit="2"/>
  </items>
</examSession>
```

실제 문항 수와 배점은 시험 형식 분석 및 회차 목표 확정 후 설정한다. 위 예시는 데이터 구조 설명용이며 실제 시험지 구성이 아니다.

### 4.3 풀이 이력 데이터

문항 원본의 `attemptCount`, `correctCount`는 누적 통계 필드로 유지한다. 개인별 오답 재출제를 위해서는 단순 집계만으로 부족하므로 별도 풀이 이력이 필요하다.

권장 이력 항목:

- `userKey`: 개인 로컬 사용자 식별 키
- `sessionId`: 풀이한 회차
- `questionId`: 원본 문항 ID
- `isCorrect`: 정오답
- `answeredAt`: 풀이 시각
- `selectedAnswer`: 선택·작성 답안
- `reviewStatus`: 오답 복습 상태

개인별 상세 이력은 추후 DB화할 때 정규화할 수 있도록 설계한다. 현재는 개인 로컬 저장을 전제로 한다.

## 5. 출제 로직 의사코드

### 1차

1. 4개 단원 원본 풀을 읽는다.
2. 전체 범위에 해당하는 문항만 후보로 선정한다.
3. 단원별 분량·개념 중요도에 따라 출제 수를 배분한다.
4. 동일 개념 및 문항 유형의 과도한 연속을 제한한다.
5. 출제 순서를 섞고 회차 XML에 문항 ID를 저장한다.

### 2차

1. 직전 회차의 풀이 이력을 조회한다.
2. 오답 문항을 우선 후보로 선정한다.
3. 목표 문항 수에 부족한 만큼 미출제 원본·예비 신규 문항을 채운다.
4. 오답 문항과 신규 문항을 섞어 배치한다.
5. 회차 XML에 원본 ID, 신규 ID, 출제 이유를 기록한다.

### FINAL

1. FINAL 전용 풀만 조회한다.
2. 2026 시험범위와 일치하는지 확인한다.
3. 기출 분석으로 확정한 단일 출제 형식에 맞춰 세트를 구성한다.
4. 총점, 문항별 배점 합계, 문항 유형 수, 정답 및 채점 기준을 자동 검사한다.
5. FINAL 전용 세션으로만 배포한다.

## 6. FINAL 기출 분석 체크리스트

2025 기출 PDF에서 아래 항목을 실제로 추출한 뒤 최종 FINAL 명세를 확정한다.

- 전체 문항 수와 총점
- 객관식·주관식·서술형 문항 수
- 문항별 배점과 배점 합계
- 단답형과 서술형의 구분 및 답안 길이
- 지문·보기·표·그림 등 자료의 사용 빈도와 배치
- 발문 유형(적절한 것/적절하지 않은 것/이유 설명/적용 등)
- 선택지 길이와 오답 유도 방식
- 교과 개념을 직접 확인하는 문항과 여러 개념을 통합 적용하는 문항의 비중
- 서술형 채점 기준과 부분점수 구조

**중요:** 이 보고서 작성 시점에는 PDF 파일 경로는 저장소에서 확인했으나, 2025 기출 PDF의 페이지별 문항·배점 분석은 아직 수행하지 않았다. 따라서 위 항목에 수치나 실제 스타일 특징을 임의로 기입하지 않는다. 교과서 시험범위 PDF의 본문 대조도 FINAL 문항 제작 직전에 수행한다.

## 7. 구현 순서

1. 기존 150문항 원본 풀을 수정 없이 보존한다.
2. 시험 회차 XML 스키마와 출제 정책을 확정한다.
3. 1차 전체 범위 조합 세트를 만든다.
4. 2차 오답 + 신규 문항 선정 로직을 만든다.
5. 풀이 이력 저장 구조를 연결한다.
6. 2025 기출의 형식 분석을 완료한다.
7. 교과서 2026 범위에 맞춰 FINAL 전용 문항을 제작한다.
8. FINAL 세트의 문항 수·배점·유형·정답·해설을 검수한다.

## 8. 변경 금지 및 안전장치

- `main` 브랜치에는 반영하지 않는다.
- 기존 daily 학습 앱의 `index.html`, `data/manifest.json`, `data/days/`를 변경하지 않는다.
- 기존 문항 원본을 회차별로 복제하거나 수정하지 않는다.
- FINAL 전용 문항이 일반 회차 후보에 섞이지 않도록 출처 풀을 분리한다.
- 실제 풀이 결과가 없는 난이도2·정답률은 추정하지 않는다.
- 시험 형식 수치와 기출 스타일 특징은 PDF에서 확인한 값만 기록한다.
