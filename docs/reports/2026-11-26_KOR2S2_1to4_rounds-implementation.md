# 중2 국어 1~4차 학습 회차 연결 작업

- 작업일: 2026-11-26
- 저장소: `g9inlife-blip/study_daily_han`
- 반영 브랜치: `main`

## 수정 이유

시험 메뉴에서 FINAL만 보이고 1~4차 학습 회차가 노출되지 않는 문제를 수정했다. 기존 문제은행 XML은 삭제되거나 수정하지 않고, 웹 시험 화면에서 불러오는 기능을 추가했다.

## 회차 구성

- 1차: 4개 단원 전체 범위의 통합 문제 30문항.
  - 기존 통합 문제은행 `drafts/question-bank/중2_2학기_국어_기말_문제은행_150문항.xml`에서 단원별 문항을 고르게 섞어 편성한다.
  - 단원별 30문항을 따로 시험하는 방식이 아니다.
- 2차: 1차의 오답 + 미출제 신규 문항으로 30문항 구성.
- 3차: 2차의 오답 + 미출제 신규 문항으로 30문항 구성.
- 4차: 3차의 오답 + 미출제 신규 문항으로 30문항 구성.
- 오답은 바로 직전 차수의 최신 제출 결과만 사용한다. 이전 차수에서 틀렸더라도 직전 차수에서 맞힌 문항은 자동 재출제되지 않는다.
- 미출제 신규 문항은 기존 통합 150문항 풀에서 선택하며, 부족할 때 예비 문제은행을 이용한다.
- FINAL은 기존 26문항 예상 기말고사로 유지되며 1~4차와 별도 제공된다.

## 웹 화면 기능

- 시험 탭에 1차~4차 회차 카드 추가.
- 이전 회차 제출 전에는 다음 회차를 잠금.
- 회차별 객관식/주관식 입력, 제출 확인, 자동 채점 및 해설 표시.
- 결과 점수와 오답 수를 보여 주고 다음 회차로 이동할 수 있게 함.
- 회차 결과는 `study_daily_han_round_results_v1` 로컬 저장 키에 기록.
- FINAL 기록 키 `study_daily_han_final_exam_results_v1` 및 매일공부 기록과 분리.
- 페이지를 새로 열어도 저장된 직전 회차 오답의 원본 문항을 XML에서 다시 불러올 수 있도록 문항 원본 참조를 기록.

## 시험 화면 초기화 오류 복구

- 확인된 핵심 오류: `initRounds()`와 회차 렌더링 함수는 있었지만, HTML에 `roundCards`, `roundExamArea`, `submitRoundBtn` 요소가 누락되어 있었다.
- 이로 인해 초기화 중 존재하지 않는 요소에 접근해 오류가 발생할 수 있었고, 시험 화면에 FINAL만 나타나는 증상이 발생했다.
- `roundsCard` 및 회차 응시 영역 HTML을 `subject-korean` 아래에 복구했다.
- 회차 HTML 복구 후 `index.html` JavaScript 문법 검사 통과.
- 정적 ID 검사: HTML ID 56개, 중복 ID 0, `el('...')`에서 참조하는 정적 요소 누락 0.

## 오류 수정 및 추가 점검

- 통합 문제은행 XML은 총 150문항이며, 기본 문항 120개와 `reserve="true"` 예비 문항 30개가 함께 들어 있음을 확인했다.
- 기존 편성 코드가 통합 파일의 예비 문항까지 1차 신규 문항 후보에 포함할 수 있어 수정했다. 이제 기본 1~4차는 예비 표시가 없는 120문항에서 출제하고, 별도 예비 XML은 기본 문항이 부족할 때만 사용한다.
- 1차 재응시를 새 학습 사이클로 처리하도록 수정했다. 새 1차를 제출하면 이전 사이클의 2~4차 기록은 다음 회차 잠금 해제 및 오답 선택에 사용하지 않는다.
- 2~4차 신규 문항 추적은 전체 과거 기록이 아니라 현재 사이클의 직전 단계별 최신 응시 기록을 기준으로 한다. 반복 학습으로 전체 문제은행이 과거 기록에 의해 소진되는 문제를 방지한다.
- XML 정적 검사: 통합 문제은행 150문항, ID 중복 0, 유형 객관식 125/주관식 25, 필수 발문·정답·해설·심화해설 누락 0. 예비 XML 30문항, ID 중복 0, 객관식 25/주관식 5, 필수 필드 누락 0.
- JavaScript 문법 검사 재실행 통과.

## 보존 및 검증

- 기존 1~4단원 문제은행 XML 및 예비 XML은 변경하지 않았다.
- 기존 매일공부 데이터와 FINAL XML/응시 기록은 변경하지 않았다.
- `index.html`의 JavaScript 문법 검사를 수행했고 통과했다.
- 실제 모바일 브라우저에서 응시·제출·새로고침·회차 잠금/해제까지 수행하는 E2E 테스트는 아직 하지 않았다. 실제 사용 시 문제 로드와 회차 이동을 확인해야 한다.
