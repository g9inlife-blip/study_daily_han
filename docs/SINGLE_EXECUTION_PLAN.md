## 1. 요약 및 의사결정

이 문서는 기존 HTML 실행안을 제품·기술·운영·수익·법적 준비를 하나의 순서로 묶은 실행 기준안이다. 기존 HTML은 원본 자료로 보존한다.

### 제품 방향

- 중학생을 중심으로 매일 짧게 학습하는 교과 학습 서비스
- 학습자 화면은 학습에 집중하고 광고와 결제는 보호자 영역에서 관리
- 매일 5문항(객관식 3, 자동 채점 가능한 단답형 2), 영어 단어 2개와 숙어 2개를 기본 구성으로 유지
- 제출 후 정답과 해설을 바로 제공하며, 정답을 광고 뒤에 숨기지 않는다
- 학습 이력과 오답 복습을 핵심 가치로 발전시킨다
- 초기 웹 버전은 정적 콘텐츠와 브라우저 로컬 기록으로 운영하고, 다기기 동기화는 서버 기반 계정 단계에서 구현한다

### 사업 방향

- 유료 패밀리 플랜의 기준 가격 가설: 월 4,900원
- 3개월 DAU 5,000은 목표 시나리오이며, 시장 검증된 예측이 아니다
- 유료 결제·광고·아동 개인정보 처리 기능은 법률 및 플랫폼 정책 검토를 통과한 후에만 활성화한다
- 교육지원청의 서면 사전상담과 만 14세 미만 보호자 동의 설계가 선행 관문이다

### 반드시 보류할 결정

**부모가 리워드 광고를 보고 받은 이용권을 연결된 자녀가 사용하는 구조는 정책 확인 전 출시하지 않는다.** Google AdMob 보상 정책은 보상이 동일 사용자에게 귀속되고 양도 불가해야 한다고 설명한다. 부모 계정의 보상을 자녀 프로필이 소비하는 구조가 허용되는지 공식 확인이 필요하다. 또한 광고를 보지 않은 경우 핵심 서비스 이용이 제한되는 방식이 rewarded ad 정책의 자발성·정상 이용 조건과 충돌하는지 검토해야 한다.

## 2. 제품 구조

### 2.1 역할 분리

| 영역 | 보호자 | 학습자 |
|---|---|---|
| 계정 | 가입, 본인 확인, 자녀 연결·해제 | 보호자 승인 후 활성화 |
| 결제 | 결제·구독·해지·환불 | 결제 기능 없음 |
| 광고 | 정책 검토를 통과한 경우에만 선택 시청 | 광고 미노출을 기본 원칙으로 함 |
| 학습 | 진도·점수·취약 단원 확인 | 문제 풀이, 정답·해설 확인 |
| 데이터 | 연결된 학습자의 필요한 기록만 조회 | 본인 학습 기록 확인 |

보호자와 학습자 계정이 분리되더라도, 연결된 계정의 권한은 서버에서 검증한다. 초대코드는 만료·회수·재발급을 지원하고 공개 URL에 점수나 개인정보를 포함하지 않는다.

### 2.2 학습 루프

1. 날짜와 학습 세트를 선택한다.
2. 문제를 풀고 답안을 제출한다.
3. 제출 전 모든 필수 문항에 답했는지 확인한다.
4. 채점 후 문제별 정답·해설·점수를 표시한다.
5. 틀린 문제를 오답 복습 목록에 넣는다.
6. 주간 결과에서 과목·단원별 약점을 확인한다.

주관식은 자동 채점 가능한 숫자·단어·짧은 구절만 사용한다. 풀이 과정이나 이유를 자유롭게 서술하게 하지 않는다. 문제 생성 규칙과 검수는 `QUESTION_GENERATION_WORKFLOW.md`를 기준으로 한다.

## 3. 기능 범위와 단계

### MVP — 현재 정적 웹 단계

- 날짜별 XML 학습 콘텐츠
- 객관식·단답형 채점
- 문제별 해설
- 날짜별 점수와 시도 기록
- 주간 문제 세트 및 일요일 오답 복습

- 콘텐츠 XML 검증 및 GitHub Actions 배포

현재 MVP에서는 실제 사용자 계정, 결제, 광고 SDK, 서버에 아동 개인정보 저장을 하지 않는다.

### 다음 단계 — 보호자 계정·클라우드

- 보호자 인증 및 학습자 연결
- 법정대리인 동의와 동의 증빙
- 사용자별 학습 기록 저장
- 보호자 리포트
- 탈퇴·삭제 및 데이터 내보내기
- 사용자별 권한 정책과 접근 테스트

### 후속 단계 — 유료·앱

- 유료 기능은 교육 관련 등록·세무·전자상거래 절차 확인 후 개발·활성화
- 앱은 PWA 검증 이후 필요성이 확인되면 네이티브 또는 단일 코드베이스로 검토
- 광고는 플랫폼 정책과 아동 보호 설계를 검토한 후 보호자 영역에 한정
- 앱스토어 정책, 계정 삭제, 개인정보 공개 문서, 결제·환불을 출시 체크리스트에 포함

## 4. 가격과 수익 모델

### 4.1 가격 가설

- 패밀리 플랜: 월 4,900원
- 무료 이용과 유료 이용의 차이는 문제의 정답·해설 접근이 아니라, 기록 아카이브·오답노트·진단·주간 모의고사·보호자 리포트 등 누적 기능으로 설계한다
- 가격은 베타에서 실제 결제 의향·전환율·환불률을 측정해 재검토한다

무료 이용권을 광고 시청으로 갱신하는 모델은 정책 검토를 통과하기 전에는 기본안으로 확정하지 않는다. 정책상 보상이 허용되지 않거나 정상 이용을 제한하는 것으로 해석될 경우, 무료 기본 이용 + 선택적 유료 기능 또는 보호자 대상 별도 광고 모델로 수정한다.

### 4.2 재현 가능한 계산

HTML의 기본 시나리오를 재현하기 위한 계산식이다. 실제 매출 전망으로 사용하지 않는다.

- 유료 가구 수 = DAU × 유료 전환율
- 유료 순매출 = 유료 가구 수 × 월 가격 × (1 − 가정한 결제 수수료)
- 광고 수익 = 광고를 실제 시청한 보호자 수 × 시청 횟수 × 채움률 × eCPM ÷ 1,000 × 환율
- 월 순수익 = 유료 순매출 + 광고 수익 − 서버·AI·스토어·인증·세무·운영 비용

HTML의 기준 가정은 DAU 5,000, 전환율 3%, 월 4,900원, 결제 수수료 15%, 부모 광고 eCPM $5.62, 채움률 88%, 환율 1,300원, 월 비용 약 49,000원이다. 이 가정에서 월 순수익 약 89만 원이라는 결과가 나온다.

**수치 해석 원칙**
- DAU 5,000 및 전환율 2~5%는 검증된 시장 예측이 아니라 목표·민감도 분석이다.
- eCPM, 채움률, 광고 시청 유지율은 국내 실제 데이터로 대체해야 한다.
- 세금, 인증비, 환불, 고객지원, 콘텐츠 검수 인건비, 앱 결제 수수료는 실제 비용으로 추가한다.
- ‘순수익’은 세금과 창업자 인건비를 모두 차감한 순이익과 다르다. 문서와 대시보드에서 용어를 분리한다.

## 5. 기술 아키텍처

### 5.1 단계별 구성

| 단계 | 구성 | 목적 |
|---|---|---|
| 현재 | GitHub 저장소 + 정적 웹 + XML + localStorage | 학습 기능 검증 |
| 공개 테스트 | 정적 호스팅 + CDN + 사용자 데이터 없는 공개 콘텐츠 | 콘텐츠·UX 테스트 |
| 계정 단계 | 인증 + DB + 서버 API + 권한 정책 | 여러 기기 기록 동기화 |
| 유료 단계 | 결제 제공자 + 구독 상태 + 환불·해지 흐름 | 상용 거래 |
| 확장 단계 | 문제 은행 + 생성·검수 파이프라인 + 분석 | 학년·과목 확장 |

### 5.2 호스팅

GitHub Pages는 현재 테스트 및 공개 학습용으로 사용한다. 공식 제한 문서에 따르면 Pages는 온라인 사업, 전자상거래 또는 상업 SaaS를 주된 목적으로 하는 무료 호스팅으로 사용할 수 없다. 따라서 가입·결제·상용 SaaS 기능을 운영할 호스팅으로 간주하지 않는다.

상용 이전 후보는 HTML에서 제안한 Cloudflare Pages + Supabase 서울 리전 조합을 우선 검토하되, 실제 배포 전에 요금·서비스 약관·지역·백업·개인정보 처리 조건을 확인한다. 특정 공급자를 영구 확정하기 전에 월간 사용량과 기능 요구사항을 측정한다.

### 5.3 데이터 분리

- 공개 콘텐츠: 날짜별 XML 또는 공개 가능한 콘텐츠 데이터
- 정답·해설: 초기 정적 버전에서는 브라우저에서 확인 가능하다는 한계를 명시
- 계정·동의·학습 기록·결제 상태: 상용 단계에서는 서버 데이터베이스
- 비밀키: HTML, JavaScript, XML, 공개 Git 저장소에 저장하지 않음
- 정답 노출 방지나 공정한 시험이 필요한 경우 문제와 정답을 서버에서 분리하고 서버 채점으로 전환

## 6. 콘텐츠·학습 데이터 운영

문제 데이터는 XML을 기준 형식으로 유지하고, DB화 시 XML의 의미를 손실 없이 옮길 수 있도록 안정적인 문제 ID와 메타데이터를 갖춘다.

문항 기본 메타데이터:

- 학년(중학교/고등학교 구분 포함)
- 과목
- 범위(교육과정·목차 기준 단원/소단원)
- 난이도(문항 작성 시 판단)
- 난이도2(누적 정답률 통계로 보정)
- 문제, 선택지, 정답
- 해설, 심화해설
- 문제를 푼 인원 수, 정답 인원 수
- 출처·저작권 검토 상태
- 콘텐츠 버전 및 검수 상태

문제 생성은 월간 캘린더를 먼저 확정하고 5일 단위로 생성·검수한다. 자동 생성 문제를 검수 없이 배포하지 않는다. 자세한 규칙은 `QUESTION_GENERATION_WORKFLOW.md`를 따른다.

## 7. 개인정보·보안 기준

- 실명 대신 별칭을 기본으로 하고, 학교·주소·생년월일 등 불필요한 정보를 수집하지 않는다.
- 만 14세 미만 이용자의 개인정보를 동의에 근거해 처리하는 경우 법정대리인 동의 및 동의 확인 절차를 구현한다.
- 동의 완료 전에는 학습 기록 수집·계정 활성화를 제한한다.
- 보호자 동의 증빙은 동의 시각, 동의 버전, 확인 방법 등 필요한 항목만 보관한다.
- 사용자별 데이터 접근 권한을 서버에서 검사한다. 클라이언트 UI에서 숨기는 것만으로 접근 제어를 구현하지 않는다.
- 탈퇴·삭제, 데이터 내보내기, 보호자 연결 해제, 보유기간 및 파기 절차를 구현한다.
- 개인정보 처리방침에 위탁·국외 이전·보유기간·권리 행사 방법을 실제 운영과 일치하게 기재한다.
- 유출 대응·통지·신고 절차를 운영 문서로 마련한다.

## 8. 법률·플랫폼 정책 출시 게이트

이 절은 법률 자문이 아니다. 서비스 구조에 따라 적용이 달라질 수 있으므로, 법률·기관·플랫폼의 확인을 기록한 뒤 출시한다.

### Gate A — 교육 관련 등록

유료로 중학생 교과 학습을 지속 제공하는 서비스가 학원법상 원격학원 또는 다른 교육시설 등록·신고 대상인지 관할 교육지원청에 서면으로 질의한다. 기존 HTML에 기재된 학원법과 평생교육법 해석의 차이는 문서만으로 확정하지 않는다.

확인할 내용:
- 서비스가 학원 또는 원격학원 등록 대상인지
- 필요한 시설·강사·교습비 등록 요건
- 사업자등록 및 통신판매업 신고 요건
- 등록 전 가능한 무료 테스트 범위
- 교육용 콘텐츠·교습 과정에 적용되는 표시·환불 의무

### Gate B — 아동 개인정보

- 연령 확인은 최소 정보로 설계한다.
- 만 14세 미만 법정대리인 동의와 확인 방법을 개인정보보호법 및 시행령에 맞춘다.
- 동의 미완료 상태에서 계정 활성화나 학습 데이터 수집을 하지 않는다.
- 아동에게는 이해하기 쉬운 문장으로 개인정보 처리 내용을 안내한다.

### Gate C — 광고 및 보상

- 리워드 광고는 사용자가 명확히 선택해야 한다.
- 광고를 건너뛰거나 거절해도 정상적인 서비스 이용을 방해하지 않는지 검토한다.
- 보상은 광고를 본 동일 사용자에게 귀속되고 양도 불가해야 한다는 정책을 검토한다.
- 부모 보상을 자녀 계정에서 사용하게 하는 가족 내 보상 이전 구조는 Google의 공식 정책 확인 전 금지한다.
- 보상 조건, 횟수, 만료, 광고 미제공 시 처리 방식을 광고 전에 명확히 표시한다.
- 자녀 화면은 광고 없는 구조를 유지한다.

### Gate D — 구독·전자상거래

- 사업자 정보, 가격, 결제 주기, 자동갱신, 해지, 환불, 청약철회 조건을 결제 전에 명확히 제공한다.
- 가격 인상 또는 무료에서 유료 정기결제로 전환할 때 필요한 별도 동의·고지 시기를 확인한다.
- 해지는 가입보다 어렵지 않게 구현한다.
- 환불·청약철회 및 디지털 콘텐츠 공급 관련 예외는 실제 상품 유형에 맞춰 검토한다.
- 통신판매업 신고 등 필요한 절차를 마친 후 결제를 활성화한다.

### Gate E — AI 콘텐츠 표시와 저작권

- AI 기반 서비스 및 생성 결과에 관한 고지·표시 의무를 현행 인공지능기본법과 시행령 기준으로 확인한다.
- 교과서 본문, 기출문제, 유료 문제집을 그대로 복제하지 않는다.
- 교육과정의 개념·성취기준을 참고해 문제와 지문을 자체 작성한다.
- 출처가 있는 자료는 출처와 사용 권한을 기록한다.
- AI 생성 콘텐츠는 사실·정답·해설 검수를 거쳐 배포한다.

## 9. 90일 실행 로드맵

기간은 계획 구간이며, 법률·정책 확인이나 품질 게이트가 통과되지 않으면 다음 단계로 넘어가지 않는다.

| 구간 | 작업 | 완료 조건 |
|---|---|---|
| 1–7일 | HTML 실행안과 기존 문서 정합성 확인, 교육지원청·세무 상담 질의 작성 | 서면 질의 접수 |
| 8–20일 | MVP UX·콘텐츠 검증, 도메인·호스팅 이전 조사 | 콘텐츠 오류 및 배포 절차 검증 |
| 21–35일 | 보호자 계정·동의 흐름 설계, 개인정보 문서 초안 | 동의 미완료 상태 차단 테스트 |
| 36–50일 | 서버 저장·보호자 리포트·권한 정책 | 사용자 간 데이터 접근 차단 테스트 |
| 51–65일 | 무료/유료 모델과 광고 정책 확인, 가격 베타 설계 | 광고·보상·결제 정책 서면 확인 |
| 66–80일 | 결제·해지·환불·삭제 흐름, 운영 모니터링 | 테스트 거래와 환불 시나리오 통과 |
| 81–90일 | 제한 베타, 지표 검토, 출시 결정 | 법·정책·품질·운영 게이트 모두 통과 |

DAU 5,000을 90일 내 달성하지 못했다고 기능 개발을 무조건 중단하지 않는다. 유입·재방문·학습 완료율·보호자 동의 완료율·유료 전환·환불률을 함께 보고 판단한다. HTML의 DAU 500/2,000/5,000 단계는 검증용 목표로 유지하되 보장된 성장 예측으로 표현하지 않는다.

## 10. 핵심 지표와 중단 조건

### 제품 지표

- 일간/주간 활성 학습자
- 학습 시작 대비 완료율
- 날짜별 재방문율

- 과목·단원별 학습 편중

### 사업 지표

- 보호자 가입 및 동의 완료율
- 유료 전환율
- 무료 이용 갱신율(정책 승인된 모델에 한함)
- 결제 실패율·환불률·해지율
- 사용자당 운영비와 콘텐츠 검수 비용
- 광고 수익은 실제 노출·시청 데이터를 기준으로 별도 측정

### 중단 또는 재설계 조건

- 교육지원청이 등록 필요로 판단했으나 필요한 요건을 충족할 수 없는 경우: 유료 운영을 보류하고 무료 학습 서비스 범위 재검토
- 광고 플랫폼이 가족 간 보상 이전을 허용하지 않는 경우: 부모 리워드 → 자녀 이용권 모델 폐기
- 아동 동의 절차가 검증되지 않은 경우: 계정·기록 수집 기능을 공개하지 않음
- 데이터 권한 테스트에서 다른 사용자 기록이 노출되는 경우: 베타 중단
- DAU 목표 미달: 유료·앱 개발을 자동 중단하기보다 유입과 유지율을 먼저 재검토하고, 비용 확대는 보류
