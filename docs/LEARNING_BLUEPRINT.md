# 학습 시스템 청사진 — 고려대 입시 기반 일일 학습 플랫폼

- 문서 버전: 1.0
- 작성 기준일: 2026-11-24
- 대상 저장소: `g9inlife-blip/study_daily_han`
- 현재 시작점: 중학교 2학년 2학기
- 장기 확장: 중3 → 고1 → 고2·고3
- 문서 목적: 문제 생성 배치를 만들기 전에 학습 목표, 콘텐츠 기준, 화면, 데이터, 저장·공유 방식의 공통 기준을 확정한다.

---

## 1. 프로젝트 방향

이 프로젝트는 매일 문제를 제공하는 단순 퀴즈가 아니라, 학교 교과 진도를 따라가면서 개념 이해와 사고력을 누적하고, 학습자와 보호자가 학습 결과 및 변화 추이를 함께 확인하는 **장기 학습 관리 웹앱**이다.

입시 목표는 고려대학교 진학이다. 다만 특정 대학 합격을 보장하거나 중학교 단계에서 수능형 고난도 문제만 앞당겨 푸는 방식은 지양한다. 현재 학년의 교과 이해를 탄탄히 하고, 읽기·수학적 사고·과학적 추론·역사적 맥락·영어 독해와 어휘를 꾸준히 성장시키는 것을 우선한다.

### 핵심 원칙

1. **교과 진도 우선**: 문제의 단원은 학년·학기·학교 진도와 맞아야 한다.
2. **학습을 위한 문제**: 정답만 고르는 퀴즈가 아니라 근거를 찾고 풀이를 설명하게 한다.
3. **매일 작은 누적**: 평일 1일 1과목 집중 + 영어 어휘·숙어를 매일 반복한다.
4. **오답은 재학습 자료**: 틀린 문제를 표시하는 데서 끝내지 않고, 원인과 다음 학습 행동을 연결한다.
5. **부모와 학습자 화면 분리**: 학습자는 풀이와 해설, 보호자는 결과·추이·취약 영역을 확인한다.
6. **콘텐츠와 화면 분리**: HTML/JavaScript는 문제를 하드코딩하지 않고 XML 데이터로 문제를 읽는다.
7. **과목 확장 가능**: 과목 추가 시 화면 로직을 크게 수정하지 않고 과목 설정과 XML 데이터로 확장한다.
8. **기록의 지속성**: 브라우저 임시 기록에만 의존하지 않도록 저장·백업·동기화 전략을 단계적으로 갖춘다.
9. **기존 기능 보존**: 현재 날짜 선택, XML 로딩, 채점, 결과 추세, JSON 내보내기/가져오기는 기준 기능으로 흡수한다.

## 2. 현재 저장소 상태와 흡수할 기능

현재 저장소에는 단일 `index.html`, `data/manifest.json`, `data/days/YYYY-MM-DD.xml` 구조가 있으며, 2026-11-24부터 2026-12-04까지의 평일 학습 데이터가 등록되어 있다.

### 이미 구현되어 있는 기능

- 날짜별 XML 문제 로딩
- manifest 기반 날짜·요일·과목·단원 선택
- 객관식 선택 및 주관식 입력
- 100점 만점 채점
- 채점 후 정답과 설명 표시
- 날짜별 재풀이 기록
- 점수 추세 그래프, 과목별 평균, 최근 평균, 연속 풀이일
- 약한 단원 목록
- JSON 기록 내보내기/가져오기
- 부모에게 보낼 결과 텍스트 복사
- GitHub Pages에 배포 가능한 정적 페이지 구조

이 기능들은 버리지 않고 개선 기반으로 사용한다.

### 현재 구조의 한계와 개선 기준

| 현재 | 한계 | 청사진 기준 |
|---|---|---|
| localStorage 저장 | 동일 브라우저·기기에 종속 | 초기 백업 + 추후 계정 기반 클라우드 저장 |
| 결과 복사로 부모 공유 | 보호자가 직접 추이를 확인하기 어려움 | 보호자 대시보드와 공유 연결 |
| XML에 정답 포함 | 정적 파일을 열면 정답을 볼 수 있음 | 초기 학습용으로 수용하되, 정답 보호가 필요하면 서버 채점 구조로 전환 |
| 날짜별 고정 manifest | 진도 변경 및 학년 확장 시 관리가 어려움 | 학습 캘린더와 커리큘럼 메타데이터 분리 |
| 오답을 단원 단위로 집계 | 문제별 오답 원인·재학습 여부가 부족 | 문제 ID, 개념 태그, 오답 유형, 재학습 상태 기록 |
| 주관식 키워드 포함 채점 | 표현이 다른 정답을 오답 처리할 수 있음 | 자동 채점은 참고 점수, 모범답안과 채점 기준을 명시 |
| 한 파일에 UI·로직·스타일 | 기능이 늘면 수정 위험 증가 | 점진적으로 CSS/JS 모듈 분리 |

## 3. 학습 일정과 과목 운영

### 3.1 기본 주간 로테이션

| 요일 | 집중 과목 | 기본 학습 |
|---|---|---|
| 월요일 | 국어 | 교과 지문·문학·문법·작문 |
| 화요일 | 수학 | 해당 학기 핵심 개념·유형·응용 |
| 수요일 | 과학 | 개념·자료 해석·실험 및 추론 |
| 목요일 | 역사/사회 | 시대 맥락·사료·자료 해석·인과관계 |
| 금요일 | 영어 | 교과 문법·독해·문장 구조·표현 |

요일은 기본값이다. 학사 일정, 시험 기간, 학교 진도 또는 보호자 설정에 따라 과목을 바꿀 수 있어야 한다.

### 3.2 매일 영어 루틴

집중 과목과 관계없이 매일 영어를 짧게 반복한다.

- 단어 2개
- 숙어·구동 표현 2개
- 단어마다 품사, 뜻, 예문, 예문 해석
- 숙어마다 의미, 자연스러운 예문, 예문 해석
- 뜻을 가리고 회상하는 방식과 예문 속 문맥 이해를 함께 사용
- 학습한 어휘는 다음 날·일주일 후·한 달 후 다시 출제할 수 있도록 복습 기록과 연결

금요일 영어 집중일에는 위 어휘 학습에 더해 영어 교과 문제 5개를 제공한다.

### 3.3 일일 문제 수와 유형

기본 일일 구성은 집중 과목 5문제다.

- 객관식 3문제
- 주관식 2문제
- 기본 배점: 문제당 20점, 총 100점
- 영어 어휘 2개 + 숙어 2개는 별도 학습 카드로 제공하며 5문제 점수에 포함하지 않는다.

문제 유형은 과목별 특성을 반영한다. 모든 과목에 동일한 문항 형식을 강제하지 않는다.

#### 수학 기준

- 객관식 2문제: 중간 난이도, 핵심 개념과 대표 유형
- 객관식 1문제: 고난도, 여러 개념의 연결 또는 조건 해석
- 주관식 2문제: 계산·풀이 과정 1문제, 이유 설명·응용 1문제를 기본으로 한다.
- 풀이 과정이 중요한 문제는 정답만 입력하게 하지 않고 풀이 또는 핵심 단계 입력을 요구한다.
- 중학교 수학의 개념을 완전히 익히기 전에 고등 수학 기호나 수능 수준의 선행을 과도하게 넣지 않는다.

#### 국어 기준

- 해당 학년·학기 교과서에 수록된 작품·지문·학습 요소를 중심으로 구성한다.
- 저작권이 있는 교과서 지문을 임의로 통째로 복제하지 않는다. 사용자가 제공한 자료 또는 허용된 인용 범위, 자체 제작 지문·요약·발췌를 활용한다.
- 단순 내용 확인보다 다음 학습 활동을 포함한다.
  - 핵심 문장과 중심 내용 찾기
  - 문단 구조와 글의 전개 방식 분석
  - 인물·화자·표현법·정서와 근거 연결
  - 어휘의 문맥상 의미 추론
  - 선택지의 근거 문장을 제시하거나 짧게 서술
- 지문은 문제 풀이에 필요한 만큼 제공하고, 각 문제에 지문 근거 또는 해설을 연결한다.

#### 영어 기준

- 중2 교과 진도에 맞는 문법·어휘·문장 구조를 중심으로 한다.
- 교과서 대화문·본문의 학습 목표를 활용하되, 저작권상 전체 본문을 무단 복제하지 않는다.
- 문법 규칙 암기만이 아니라 문장 완성, 문맥상 어휘, 짧은 독해, 문장 순서, 오류 수정 등을 섞는다.
- 영어 집중일 5문제는 객관식 3 + 주관식 2를 기본으로 하되, 서술형은 문장 작성 또는 근거 설명으로 구성한다.

#### 과학 기준

- 교과 개념을 먼저 확인한 뒤 현상 설명, 그래프·표·실험 결과 해석으로 확장한다.
- 관찰 사실과 추론을 구분한다.
- 실험 문제에는 변인, 대조 조건, 결과 해석, 오차 가능성 중 적어도 하나를 다룬다.
- 계산 문제는 단위와 과정이 정확한지 확인한다.

#### 역사/사회 기준

- 연도 암기만으로 끝내지 않고 시대적 배경, 원인과 결과, 인물·사건 간 관계를 묻는다.
- 사료·지도·표·사진 등 자료가 있을 때 출처와 시점을 명확히 한다.
- 사실 확인, 맥락 이해, 비교·추론을 단계적으로 섞는다.
- 역사와 사회를 별도 과목으로 확장할 수 있도록 과목 ID는 분리한다. 현재 주간 로테이션에서는 역사/사회 집중일을 하나의 슬롯으로 운영할 수 있다.

## 4. 교과 진도와 시기 관리

### 4.1 단원 선택 우선순위

문제 날짜의 단원은 다음 순서로 결정한다.

1. 현재 학교에서 실제로 배우는 단원
2. 해당 학년·학기의 공식 교육과정 및 교과서 순서
3. 직전 학습에서 확인된 취약 개념
4. 다음 단원의 선수 개념 복습
5. 시험 기간에는 시험 범위와 누적 복습

정확한 학교 진도와 교과서는 학교마다 다를 수 있으므로, 시스템이 월별 단원을 단정해서 고정하지 않는다. 보호자가 학습 캘린더에서 현재 단원과 진도 상태를 수정할 수 있어야 한다.

### 4.2 학습 캘린더 데이터

각 학습 계획에는 다음 정보를 둔다.

- 학년·학기
- 과목
- 단원 및 소단원
- 교과서 출판사·교과서명(선택)
- 학교 진도 시작/종료 예상일
- 실제 학습 시작/완료일
- 상태: 예정 / 학습 중 / 완료 / 복습 필요
- 시험 범위 여부
- 선수 개념 및 연결 개념

### 4.3 진도 변경 대응

학교 진도가 계획보다 빠르거나 느릴 경우 다음을 지원한다.

- 날짜별 단원 수정
- 특정 단원의 학습 기간 이동
- 이미 완료한 단원에 대한 복습 문제 삽입
- 시험 주간 집중 복습 모드
- 결석·휴일로 빠진 문제를 다음 날 몰아서 강제하지 않고 일정 재배치

## 5. 학습 경험과 화면 구성

최소 2개 화면을 기본으로 하고, 기능은 역할에 따라 확장한다.

### 화면 A — 학습자 문제 풀이

목적: 오늘 학습을 시작하고, 문제를 풀고, 채점 후 설명을 통해 배운다.

필수 요소:

1. 오늘 날짜·요일·학년·과목·단원
2. 날짜 선택 및 이전 학습 다시 풀기
3. 오늘 학습 목표(한 문장)
4. 영어 단어·숙어 카드
5. 지문 또는 자료 영역
6. 문제 목록과 답 입력
7. 진행 표시(예: 3/5)
8. 임시 답안 유지 및 제출 전 확인
9. 채점 결과
10. 정답·모범답안·해설·관련 개념
11. 틀린 문제 다시 풀기 또는 복습 예약

학습 흐름:

- 문제를 풀기 전 정답과 해설은 숨긴다.
- 학습자가 제출하면 점수를 계산하고 정답과 설명을 공개한다.
- 결과 화면에서 오답을 단순히 빨간색으로 표시하는 데 그치지 않고, 왜 틀렸는지 확인할 수 있도록 해설과 개념을 보여준다.
- 학습 완료 후 “오늘 학습 완료” 상태를 저장한다.
- 다시 풀기는 별도 시도로 기록하고, 기존 기록을 덮어쓰지 않는다.

### 화면 B — 보호자 결과·추이 대시보드

목적: 보호자가 공유된 학습자의 학습 진행과 변화 추이를 확인한다.

필수 요소:

- 오늘 학습 상태: 미시작 / 진행 중 / 완료
- 최근 점수와 최근 7일·30일 평균
- 과목별 평균 및 추세
- 단원별 정답률
- 첫 시도 점수와 재풀이 점수 구분
- 학습 시간 및 완료 빈도
- 반복 오답 개념
- 복습 예정 목록
- 날짜별 상세 결과
- 결과 내보내기 기능

추이 화면은 점수만 높이기 위한 경쟁 지표가 되지 않도록 한다. 학습량, 꾸준함, 개념별 숙련도와 함께 점수를 해석한다.

### 화면 C — 콘텐츠/진도 관리 (추후)

보호자가 학습 캘린더, 과목, 단원, 문제 세트를 등록·수정하는 관리 화면이다. 초기에는 XML과 manifest를 직접 관리해도 되지만, 데이터가 많아지면 웹 관리 화면으로 전환한다.

### 화면 D — 공유·계정 연결 (클라우드 단계)

학습자 계정과 보호자 계정을 연결하고, 보호자가 지정된 학습자의 결과만 조회하도록 한다. 공유 코드는 만료·재발급 가능해야 하며, 공개 링크로 개인 기록을 노출하지 않는다.

## 6. 채점과 학습 피드백

### 6.1 점수 체계

- 기본 점수: 100점
- 객관식: 정답 20점, 오답 0점
- 단답형: 정답·허용 답안 기준으로 20점
- 서술형: 채점 기준에 따른 부분 점수
- 미응답: 0점으로 계산하되, 학습 완료 상태와 구분한다.

서술형의 키워드 자동 채점은 보조 기능이다. 키워드가 들어갔다고 반드시 완전한 정답은 아니며, 다른 표현으로 정확히 답했는데 키워드가 없다고 무조건 오답 처리해서도 안 된다.

### 6.2 서술형 채점 기준

각 서술형 문항은 다음을 XML에 포함한다.

- 모범답안
- 필수 채점 요소
- 요소별 배점
- 허용 가능한 표현 또는 예시
- 흔한 오개념
- 해설

초기 정적 웹에서는 키워드 기반 부분 채점을 제공할 수 있지만, 결과에는 “자동 채점 참고 점수”임을 표시한다. 보호자가 필요한 경우 수동으로 점수를 조정할 수 있는 기능은 클라우드/관리 단계에서 검토한다.

### 6.3 오답 분류

문제별로 다음 중 하나 이상의 오답 원인을 기록할 수 있다.

- 개념 미이해
- 조건 또는 지문 오독
- 계산·기호 실수
- 어휘 부족
- 근거 부족
- 풀이 과정 누락
- 시간 부족
- 단순 실수
- 기타 / 학습자 직접 선택

오답 원인은 학습자가 선택하거나 보호자가 검토한다. 시스템이 답안만 보고 심리적 원인을 확정하지 않는다.

### 6.4 복습 규칙

초기 기본 복습 일정:

- 오답: 다음 학습일에 짧은 재확인
- 어려웠던 개념: 3일 후 복습
- 완료한 핵심 개념: 7일 후 확인
- 장기 유지 확인: 30일 후 재출제

복습은 같은 문제만 반복하지 않고, 같은 개념을 다른 문맥이나 문제 형식으로 다시 확인한다.

## 7. 콘텐츠 데이터 구조

### 7.1 원칙

- HTML은 화면과 사용자 인터랙션을 담당한다.

## 8. 기록 저장과 부모 공유

### 8.1 초기 저장

현재 localStorage 기록을 유지한다.

- 저장 키: 기존 `study_daily_han_results_v1`
- 기존 기록을 읽을 수 있어야 한다.
- JSON 내보내기/가져오기 기능을 유지한다.
- 기록을 삭제하기 전 확인을 표시한다.
- 내보낸 파일에 개인정보를 포함하지 않도록 학습자 표시명은 선택값으로 처리한다.

### 8.2 저장 데이터

각 시도 기록은 다음을 포함한다.

- attempt ID
- learner ID 또는 로컬 프로필 ID
- 날짜 및 학습 세트 ID
- 과목·단원
- 문제별 답안
- 문제별 점수와 정오 여부
- 문제별 오답 원인(선택)
- 총점 및 맞은 문제 수
- 시작·완료 시간
- 시도 번호
- 제출 시각
- 학습 완료 여부
- 복습 상태

답안 원문을 저장할 경우, 보호자 화면에 노출되는 범위를 명확히 한다.

### 8.3 부모가 다른 기기에서 확인하기 위한 조건

GitHub Pages는 정적 호스팅이므로 자체적으로 사용자 기록을 서버에 저장하거나 이메일·푸시 알림을 발송하지 않는다. localStorage만으로는 부모와 자녀가 서로 다른 기기에서 같은 기록을 실시간으로 볼 수 없다.

따라서 기능을 다음 단계로 나눈다.

**단계 1 — 정적 웹 + 로컬 기록**
- GitHub Pages 배포
- 기존 기록 저장 및 JSON 백업/복원
- 결과 복사 공유
- 보호자 화면은 같은 기기에서 기록 확인

**단계 2 — 계정 기반 저장**
- 인증 및 데이터베이스 서비스 연결
- 학습자와 보호자 계정 연결
- 결과를 서버에 저장하고 보호자 대시보드에서 조회
- 접근 권한은 연결된 보호자에게만 부여
- 사용자별 데이터 분리와 권한 정책 검증

클라우드 저장소는 별도 검토 후 결정하되, Supabase 등 인증·DB·권한 정책을 제공하는 서비스를 후보로 둔다. 서비스 선택 전에 무료 사용량, 백업, 한국에서의 접근성, 개인정보 처리 조건을 확인한다.

### 8.4 공유 방식

- 초기: 결과 텍스트 복사 또는 JSON 내보내기
- 이후: 보호자 계정 연결
- 공유 코드 방식은 만료·회수·재발급 지원
- 결과를 공개 URL에 그대로 노출하지 않는다.
- 보호자는 본인이 연결한 학습자만 조회한다.

## 9. 보안과 개인정보

- 학습자 이름은 실명 대신 별칭 사용을 기본으로 한다.
- 생년월일, 학교명, 학급, 주소 등 불필요한 개인정보를 수집하지 않는다.
- GitHub 저장소에는 문제 콘텐츠와 공개 가능한 설정만 올린다.
- 비밀번호, API 비밀키, 서비스 관리자 키를 HTML/JavaScript 또는 XML에 넣지 않는다.
- 정적 XML에 정답이 포함되면 브라우저 개발자 도구로 정답을 확인할 수 있다. 이는 초기 학습용 구조의 한계다.
- 정답 노출을 방지하거나 공정한 시험 모드가 필요해지면 문제/정답을 서버에서 분리하고 서버 채점으로 전환한다.
- 클라우드 단계에서는 사용자별 접근 정책을 반드시 검증한다.
- 데이터 내보내기와 삭제는 사용자가 통제할 수 있어야 한다.

## 10. 과목 확장 기준

과목은 코드에 하드코딩하지 않고 설정으로 관리한다.

과목 설정 예시:

- subject ID: `korean`, `english`, `math`, `science`, `history`
- 표시명
- 색상/아이콘(선택)
- 주간 로테이션 기본값
- 기본 문항 수
- 허용 문제 유형
- 채점 방식
- 교육과정 매핑

추후 사회, 정보, 제2외국어, 논술 등 과목을 추가할 때는 다음 절차를 따른다.

1. 과목 설정 추가
2. 커리큘럼 파일 추가
3. XML 문제 데이터 작성
4. manifest에 학습일 또는 세트 연결
5. 검증 스크립트 실행
6. 기존 결과 화면에서 과목이 자동으로 표시되는지 확인

새 과목 추가를 위해 채점 엔진이나 대시보드의 핵심 코드를 수정해야 한다면 확장 설계가 부족한 것으로 본다.

## 12. 문제 생성 배치 — 추후 구축

문제 생성 배치는 지금 구현하지 않는다. 먼저 XML 스키마, 진도 캘린더, 학습 화면, 결과 기록의 기준을 안정화한다.

추후 배치의 책임:

1. 학습 캘린더에서 대상 날짜·학년·과목·단원을 읽는다.
2. 해당 단원의 학습 목표와 난이도 분포를 결정한다.
3. 문제 초안을 생성하거나 문제 은행에서 선택한다.
4. 문제 유형·개수·배점·정답·해설을 검증한다.
5. XML well-formed 검사를 실행한다.
6. 문제 수와 객관식/주관식 비율을 검사한다.
7. 정답과 해설의 일치 여부를 검토한다.
8. 저작권·출처 메타데이터를 확인한다.
9. 검토 대기 상태로 저장한다.
10. 보호자 또는 검토자가 승인한 뒤 manifest에 등록한다.

자동 생성 문제를 검토 없이 곧바로 학습자에게 배포하지 않는다. 특히 수학 계산, 과학 사실, 역사 연도, 국어 해석, 영어 문법은 정답 오류를 별도 검증해야 한다.

## 13. 자동 전송·알림 — 추후 구축

GitHub Pages 자체는 매일 사용자에게 메시지를 보내지 않는다. 자동 알림은 별도 배치와 알림 서비스가 필요하다.

추후 설계 후보:

- GitHub Actions scheduled workflow: 날짜별 학습 세트 생성·검증·배포 자동화
- 이메일 또는 메신저 알림 서비스: 오늘 학습 링크와 학습 안내 전달
- 알림은 학습 링크 및 진행 안내만 포함하고, 점수나 개인정보를 공개 메시지에 노출하지 않는다.
- 배치 실패 시 재시도와 오류 로그를 남긴다.
- 휴일·시험 기간·학습 중단일은 캘린더 설정을 따른다.

자동 전송은 문제 품질과 기록 저장이 안정된 후 구축한다.

## 15. 완료 기준 (Acceptance Criteria)

### 학습 화면

- [ ] 날짜를 선택하면 해당 XML의 문제와 영어 학습이 표시된다.
- [ ] 학습자는 제출 전 정답을 볼 수 없다.
- [ ] 제출 후 문제별 정답·해설·점수가 표시된다.
- [ ] 완료 상태와 풀이 시간이 기록된다.
- [ ] 다시 풀기는 별도 시도로 저장된다.

### 콘텐츠

- [ ] 기본 세트는 5문제이며 객관식 3, 주관식 2이다.
- [ ] 영어 단어 2개와 숙어 2개가 매일 표시된다.
- [ ] 과목별 문항 기준과 난이도 분포를 지킨다.
- [ ] XML 파싱 오류, 누락된 정답, 잘못된 배점은 검증에서 잡힌다.
- [ ] 각 문제에 학년·과목·단원·개념 정보가 연결된다.

### 결과·추이

- [ ] 점수와 문제별 결과가 저장된다.
- [ ] 과목별·단원별 추이를 확인할 수 있다.
- [ ] 첫 시도와 재풀이가 구분된다.
- [ ] JSON 내보내기/가져오기가 기존 데이터와 호환된다.
- [ ] 부모가 학습 완료 여부와 점수 결과를 확인할 수 있다.

### 운영

- [ ] GitHub Pages에서 정상 실행된다.
- [ ] 새 과목 추가가 설정과 데이터 추가 중심으로 가능하다.
- [ ] 중3·고1 커리큘럼을 기존 기록을 유지한 채 추가할 수 있다.
- [ ] 비밀키나 불필요한 개인정보가 저장소에 포함되지 않는다.

## 16. 최종 설계 결론

이 프로젝트는 다음 구조로 발전시킨다.

- **정적 웹앱**: GitHub Pages에서 문제 풀이 화면 제공
- **XML 콘텐츠**: 날짜별 학습 세트와 문제·정답·해설 저장
- **JSON 설정**: 과목, 커리큘럼, 날짜별 학습 계획 관리
- **학습 기록**: 기존 localStorage와 JSON 백업을 초기 기반으로 유지
- **보호자 대시보드**: 점수뿐 아니라 진도·꾸준함·취약 개념·복습 상태를 확인
- **클라우드 저장**: 부모와 자녀가 다른 기기에서 확인하는 단계에서 도입
- **생성 배치**: 콘텐츠와 채점 기준이 안정된 이후 별도 구현
- **학년 확장**: 중2 → 중3 → 고1을 데이터·커리큘럼 추가로 확장

가장 중요한 성공 기준은 문제를 매일 많이 푸는 것이 아니라, 학습자가 매일 조금씩 이해하고, 틀린 이유를 확인하고, 시간이 지나도 배운 내용을 기억하도록 돕는 것이다.
