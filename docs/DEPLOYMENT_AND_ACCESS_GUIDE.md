# 배포 및 접근 제어 가이드

> 목적: `study_daily_han`을 GitHub Pages 테스트용으로만 사용하고, 실제 가족 학습 환경에서는 무료 또는 저비용 호스팅이나 가정 내 간단한 서버로 운영하기 위한 선택지와 적용 순서를 정리한다.
>
> 관련 설계 문서: [학습 시스템 설계 청사진](./LEARNING_BLUEPRINT.md)

## 1. 운영 방향

- GitHub Pages: 화면 확인, UI 개발, 기능 시연 등 **테스트 환경**으로만 사용한다.
- 실제 운영: 가족 전용 접속과 학습 결과 저장이 필요하므로 별도 호스팅 또는 가정 내 서버를 사용한다.
- 학습 기록과 개인정보는 공개 저장소, 공개 XML/JSON, 정적 HTML/JavaScript에 넣지 않는다.
- 부모와 자녀가 서로 다른 기기에서 접속하고 결과를 공유하려면 인증 및 서버 저장 기능이 필요하다.

## 2. GitHub Pages가 실제 운영에 적합하지 않은 이유

GitHub Pages는 정적 웹 호스팅이다. 일반적인 공개 Pages 사이트는 URL을 아는 사람이라면 GitHub 로그인 없이 접속할 수 있다.

정적 사이트만으로는 다음 기능을 안전하게 제공하기 어렵다.

- 부모/자녀 계정 인증 및 권한 구분
- 서버 측에서 정답을 숨긴 상태로 문제 제공 및 채점
- 부모와 자녀의 점수·진도 동기화
- 사용자별 데이터 접근 제한
- 서버에서 실행되는 일일 알림 또는 작업

또한 정적 파일에 포함된 XML/JSON의 정답은 브라우저 개발자 도구나 네트워크 요청을 통해 확인될 수 있다. 화면에서 정답을 감추는 것만으로는 보호되지 않는다.

## 3. 배포 선택지

### A. 무료 정적 호스팅 + 별도 백엔드 (가족 계정 운영에 권장)

구성 예시:

- 프론트엔드: Cloudflare Pages 등 정적 사이트 호스팅
- 인증/데이터베이스: Supabase 또는 Firebase 등 관리형 서비스의 무료 구간
- 서버 기능: 해당 서비스의 서버리스 함수 또는 Edge Function
- 주소: 호스팅에서 제공하는 HTTPS 도메인

장점:
- 별도 컴퓨터를 계속 켜둘 필요가 없다.
- HTTPS와 배포 자동화가 비교적 간단하다.
- 부모와 자녀가 서로 다른 장소·기기에서 접속할 수 있다.
- 무료 구간이 제공되는 서비스 조합으로 시작할 수 있다.

주의:
- 무료 플랜의 한도, 비활성 프로젝트 정지 정책, 저장 용량, 인증 제공 범위는 서비스별로 바뀔 수 있으므로 실제 가입 시 확인한다.
- 데이터베이스 보안 규칙/Row Level Security를 반드시 설정한다.
- API 키 중 공개용 키와 서버 비밀키를 구분한다. 비밀키는 프론트엔드 코드에 넣지 않는다.
- 문제 정답과 채점 기준은 가능하면 서버 측에 두고, 제출 후 정답·해설을 반환한다.

적용 순서:
1. 기존 HTML/CSS/JavaScript를 정적 호스팅에 배포한다.
2. 로그인 기능을 추가하고 부모와 자녀 계정을 구분한다.
3. 데이터베이스에 사용자 ID, 날짜, 문제 ID, 답안, 점수, 완료 시각을 저장한다.
4. 서버 정책으로 자녀는 자신의 학습 결과만 제출/조회하도록 제한한다.
5. 부모 계정은 연결된 자녀의 결과만 조회하도록 제한한다.
6. 정답은 제출 전 클라이언트에 전달하지 않도록 문제 제공/채점 API를 구성한다.
7. 백업·내보내기 기능을 유지한다.

### B. 가정 내 기존 PC 또는 저전력 컴퓨터를 서버로 사용

구성 예시:

- 오래된 PC, 미니 PC 또는 Raspberry Pi
- Linux 또는 사용 가능한 운영체제
- 웹 서버(예: Caddy 또는 Nginx)
- 앱/API와 데이터베이스
- 외부 접속이 필요하면 HTTPS 및 안전한 네트워크 설정

장점:
- 하드웨어를 이미 가지고 있다면 추가 호스팅 비용을 줄일 수 있다.
- 파일과 데이터베이스를 직접 관리할 수 있다.
- 가족 내부에서만 사용할 경우 외부 공개 없이 운영할 수 있다.

주의:
- 서버를 켜두어야 하고, 업데이트·백업·장애 대응을 직접 해야 한다.
- 외부 접속을 위해 공유기 포트를 무작정 열지 않는다.
- 가정 인터넷의 공인 IP, CGNAT, ISP 정책에 따라 외부 접속이 불가능하거나 복잡할 수 있다.
- 외부 접속이 필요하면 VPN(예: WireGuard 또는 Tailscale 같은 방식)으로 가족 기기만 연결하는 방식을 우선 고려한다.
- 공개 인터넷에 서버를 노출할 경우 HTTPS, 방화벽, 강한 인증, 보안 업데이트가 필요하다.

초기 권장:
1. 집 내부 Wi-Fi에서만 접속되는 로컬 웹 서버로 시작한다.
2. 부모 PC와 자녀 기기에서 접속·저장·조회가 되는지 확인한다.
3. 외부 접속이 꼭 필요할 때 VPN 방식부터 검토한다.
4. 인터넷에 직접 공개하는 포트포워딩은 보안 설정을 점검한 후 마지막 선택지로 둔다.

### C. 공유기 USB 저장장치 활용

공유기 USB 포트에 USB 메모리나 외장 HDD를 연결했다고 해서 자동으로 웹 서버가 되는 것은 아니다.

공유기 USB 기능은 모델/펌웨어에 따라 다음 중 일부만 제공할 수 있다.

- 파일 공유(SMB/FTP)
- 미디어 서버
- 다운로드 관리
- USB 저장장치 접근

파일 공유 기능은 웹 애플리케이션 서버나 인증된 데이터베이스와 다르다. HTML 파일을 공유할 수 있어도, 사용자별 로그인·API·안전한 채점·데이터베이스 기능을 제공하지 않을 수 있다.

검토할 조건:
- 공유기 모델과 펌웨어가 사용자 지정 앱/패키지 실행을 지원하는가?
- USB 저장장치에서 웹 서버 프로세스를 실행할 수 있는가?
- 저장장치 파일 시스템과 쓰기 권한이 지원되는가?
- 자동 시작, 로그, 업데이트, 백업 기능이 있는가?
- 외부 접속을 안전하게 제한할 수 있는가?

가능한 사용 방식:
- **가장 단순한 방식:** USB는 백업 파일 저장용으로 사용하고, 웹 앱은 다른 서버에서 실행한다.
- **지원 공유기:** Entware 등 패키지 환경이나 제조사 앱을 통해 웹 서버를 설치할 수 있는지 모델별로 확인한다.
- **고급 방식:** USB에 데이터 파일을 두고 공유기에서 서버 프로그램을 실행한다. 단, 공유기 CPU/RAM·저장장치 성능과 펌웨어 제약이 크므로 권장 기본안은 아니다.

권장하지 않는 방식:
- 공유기 USB 파일 공유를 인터넷에 그대로 공개
- SMB/FTP를 외부 인터넷에 포트포워딩
- 공유기 관리자 계정이나 파일 공유 계정을 자녀용 웹 앱에 내장
- 정답 파일이나 점수 파일을 공개 폴더에 저장

## 4. 선택 기준

| 기준 | 무료 관리형 호스팅 | 집의 PC/미니 서버 | 공유기 USB |
|---|---|---|---|
| 초기 비용 | 무료 구간으로 시작 가능 | 보유 장비 활용 시 낮음 | 보유 장비 활용 시 낮음 |
| 상시 전원 | 필요 없음 | 필요 | 공유기는 상시 전원 |
| 설정 난이도 | 중간 | 중간~높음 | 모델별 편차가 큼 |
| 가족 외부 접속 | 비교적 쉬움 | VPN/네트워크 설정 필요 | 대체로 제한적 |
| 계정·DB 구현 | 관리형 서비스 활용 | 직접 설치 가능 | 지원 여부 불확실 |
| 유지보수 | 서비스가 일부 담당 | 직접 관리 | 펌웨어·제약에 좌우 |
| 추천 용도 | 가족용 실제 운영 | 집 안 중심 운영/학습용 서버 | 백업 또는 실험 |

## 5. 권장 단계별 진행

### 1단계 — 테스트
- GitHub Pages에서 UI와 학습 흐름을 확인한다.
- 실제 이름, 개인 점수, 비밀 정보는 테스트 데이터로 대체한다.
- 공개 XML에 정답이 포함되어 있다는 점을 전제로 한다.

### 2단계 — 가족용 실제 운영의 최소 구성
- 무료 정적 호스팅 + 무료 구간의 인증/DB 서비스를 우선 검토한다.
- 부모/자녀 로그인과 결과 저장을 구현한다.
- 데이터 접근 정책을 검증한다.
- HTTPS 접속을 사용한다.

### 3단계 — 집 안 서버 대안
- 기존 PC 또는 저전력 장비에 로컬 서버를 설치한다.
- 공유기 내부 IP로 접속하고, 처음에는 외부 포트를 열지 않는다.
- 정기 백업을 USB 저장장치에 보관한다.

### 4단계 — 공유기 USB 실험
- 정확한 공유기 모델과 펌웨어를 확인한다.
- 제조사 문서에서 USB 저장장치와 사용자 앱 실행 지원 여부를 확인한다.
- 서버 실행이 지원되지 않으면 USB는 백업용으로만 사용한다.

## 6. 데이터 보안 및 백업 기준

- 자녀의 실명 대신 별칭 또는 내부 사용자 ID를 사용한다.
- 로그인 비밀번호는 직접 저장하지 않고 인증 서비스에 맡긴다.
- 부모는 연결된 자녀의 결과만 조회할 수 있어야 한다.
- 자녀는 다른 사용자의 결과를 조회할 수 없어야 한다.
- 문제 답안은 제출 전 클라이언트에 전달하지 않는 구조를 목표로 한다.
- 데이터베이스 권한 정책은 화면 UI와 별개로 서버에서 강제한다.
- JSON/CSV 백업을 정기적으로 내보내고, 복원 테스트도 한다.
- USB 백업은 서버 운영과 별개로 보관하며, 가능하면 두 번째 위치에도 복사한다.

## 7. 최종 권장안

현재 프로젝트는 다음처럼 분리해 운영한다.

1. **GitHub Pages:** 개발·테스트·시연 전용
2. **실제 가족 서비스:** 무료 정적 호스팅 + 인증/DB 백엔드
3. **가정 내 대안:** 기존 PC/미니 서버를 로컬 또는 VPN 전용으로 운영
4. **공유기 USB:** 우선 백업 저장장치로 활용하고, 서버 기능은 모델 지원이 확인된 경우에만 실험

이렇게 하면 GitHub Pages의 공개 특성을 실제 가족 학습 기록과 분리하면서, 비용을 거의 들이지 않고 단계적으로 확장할 수 있다.
